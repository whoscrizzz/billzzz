# Auditoría integral — 2026-08-21

Este documento consolida el estado operativo de `billzzz` como backend/PWA y su relación
con `billzzz-app` como cliente móvil. Es el espejo backend del snapshot móvil para que
seguridad, D1, backups, deploy y contrato API vivan en un mismo contexto.

## Alcance revisado

- Worker Cloudflare, rutas API, auth, passkeys, sesiones, rate limits y acciones firmadas.
- D1, migraciones, scripts de deploy/migración, backups y restore.
- PWA React, service worker, offline queue, notificaciones y documentación.
- Integración móvil consumida por `billzzz-app`.

No se ejecutaron deploys ni migraciones de producción.

## Estado actual confiable

- El Worker canónico sirve `https://billzzz.whoscrizzz.com/billzzz-api`.
- La D1 canónica de producción es `bills-pwa-db`.
- Deploy y migraciones D1 están separados; `deploy:safe` no aplica migraciones remotas.
- Las migraciones de producción exigen `CONFIRM_D1_PROD_MIGRATION=bills-pwa-db`.
- Backups cifrados están documentados y automatizados, pero falta restore drill real en
  D1 temporal.
- `billzzz-app` es cliente móvil separado; no debe cambiar schema, secrets ni D1.

## Hallazgos principales

### Seguridad

1. Sesiones opacas hasheadas en D1: buen modelo para revocación.
2. Auth invite-only evita registro abierto no deseado.
3. Falta prueba integrada final de logout móvil contra Worker.
4. Conviene minimizar respuestas públicas con proyecciones explícitas en vez de `SELECT *`.

### D1 y backup

1. La separación deploy/migración ya corrige el riesgo de modificar datos al desplegar UI.
2. Falta restaurar un backup real en D1 temporal y guardar evidencia.
3. Falta staging D1/Worker documentado antes de probar features móviles contra datos no
   productivos.
4. Cualquier migración futura debe vivir en rama dedicada, con backup reciente verificado.

### Herramientas

1. Backend declara Node 24 y tiene CI/validate robusto.
2. `npm audit`/`npm outdated` no pudieron consultar npm por red bloqueada durante esta
   auditoría; quedan como verificación externa pendiente.
3. Wrangler global reportó versión distinta a la del repo; usar `npx wrangler` desde el
   proyecto evita drift.

### Frontend/PWA

1. PWA tiene offline queue y Service Worker controlado por build checks.
2. Quedan pendientes visuales/accesibilidad del handoff anterior.
3. El calendario indicado por `?p=calendar` no renderiza el calendario completo todavía.

## Plan por ramas

1. `ops/d1-restore-drill`
   - Restaurar backup cifrado en D1 temporal y comparar tablas/conteos.
   - Criterio: evidencia documentada en `docs/BACKUPS.md`.

2. `ops/staging-d1`
   - Definir Worker/D1 staging y variables que `billzzz-app` usará en preview.
   - Criterio: ninguna prueba móvil escribe accidentalmente en `bills-pwa-db`.

3. `security/api-data-minimization`
   - Sustituir respuestas públicas con proyecciones explícitas y actualizar contrato móvil.
   - Criterio: `/subscriptions` y endpoints relacionados devuelven solo campos consumidos.

4. `test/auth-mobile-contract`
   - Añadir prueba de paridad Worker/móvil para auth, logout y suscripciones.
   - Criterio: si cambia una respuesta requerida por la app, falla `npm run validate`.

5. `quality/pwa-a11y-calendar`
   - Corregir `role=img` con hijos interactivos y render real de `?p=calendar`.
   - Criterio: accesibilidad y ruta de calendario verificadas manualmente.

6. `ops/cloudflare-inventory`
   - Confirmar Workers, custom domains, bindings, crons, secrets y tráfico en dashboard.
   - Criterio: inventario actualizado en `docs/cloudflare/inventario.md`.
